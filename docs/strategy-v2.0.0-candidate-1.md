# Strategy split — v2.0.0, candidate 1

Application base: `78df8f1fc994442a06aa9eaa411414462e169727`, v1.4.0 candidate 4.
Crate base: `cbee27824f21d6d04d52adb49a7a0266cfc7ed19`, xsar v0.1.0.
Candidate pair: application v2.0.0 candidate 1 and xsar v0.2.0 candidate 1.

## Behaviour

Startup offers Shortest path route calculation and Computer Vision solving,
with explanatory text. No connection or automatic capture occurs first.
The independent choice is explicitly preparation-only: Pyramid capture,
calibrated slot inspection and exact-byte PNG preview/save. It performs no
card recognition, route search, stock reconnaissance, Solver activation,
gameplay or terminal input. CV retains all five current game controllers.

Idle strategy switches clear authority and bookkeeping while retaining the
session log. Every request/result includes game, strategy, socket and a
selection generation. Late results from an earlier selection are ignored,
even when switching back to the same visible values. CV timings are hidden
in preparation; socket and capture controls remain available. STOP, active-run
and snapshot review gates prevent switching during owned work.

## Shared implementation

xsar adds dependency-free geometry and optional Unix QMP, validated RGBA
predicate scans and PNG decoding. Application modules reexport or adapt these
implementations. The Draw name remains local, mapped to qcode d in the shared
neutral key API. Game rules, colours, calibrated points, action selection,
terminal flow, screenshot acquisition and logging remain application-owned.
The existing telemetry exports remain available without optional dependencies.

## Local validation and promotion

The supplied guarded pair wrapper takes an explicit absolute xsar checkout
path. It verifies exact installed candidate contents in both repositories,
then passes a command-line Cargo patch. The override is not written into the
repository or global Cargo settings. The application manifest currently pins
the existing xsar Git base solely as the patch source identity; that base
lacks the new features and cannot build this app without the override.

After paired validation, Charlie promotes xsar first. A follow-up application
candidate pins that exact promoted commit and regenerates/revalidates Cargo.lock.
Only then promote the app. Crates.io publishing is a separate decision.

## Beast acceptance

Check startup without any QMP capture, each choice's explanatory text,
preparation capture/slot inspection/original-byte saving, absent gameplay
controls and hidden CV timings. Switch between preparation and CV while idle,
including back to the same game/socket. Confirm fresh frames and discarded
stale events. Exercise the five accepted CV modes with their existing timing
settings, STOP and PNG workflows. No independent-game solving is claimed.

Native validation results, exact tool versions, installer rehearsals and
current limits are supplied in the accompanying review/validation records.
